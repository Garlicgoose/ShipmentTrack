# ShipmentTrack v1.3.1

PySide6 原生 Windows 工具，用于批量查询 DHL / DSV / EI / UPS / FedEx
运单状态、下载已送达货件的 POD，以及合并并核对检验表和 Droplist。

1.3.1 修复 EI S 海运查询状态读取；保留 1.3 的 FedEx POD 双模式、UPS POD 校验和 Droplist 自检功能。

## 运行（源码）
```
pip install -r requirements.txt
python main.py
```

## 打包
```
powershell -ExecutionPolicy Bypass -File build.ps1 -DistRoot E:\ShipmentTrackBuild
# 1) PyInstaller ShipmentTrack.spec（onedir，collect_all playwright）
# 2) 将两份默认映射 JSON 复制到 data / 复制使用说明.txt
# 产物: 指定目录\Shipment Track\Shipment Track.exe（整文件夹拷贝使用）
# Edge / Google Chrome 由用户在设置页选择并自动检测
# 注意: build.ps1 必须保存为 UTF-8 with BOM（PS5.1 中文乱码问题）
# 旧 dist/data 有设置或本地运行数据时构建会拒绝覆盖，务必指定独立空目录
```

## 页面

- 跟踪：读取两列 Excel（快递公司、运单号），实时显示状态、抵达时间和备注。
- POD 抽查：设置页可为 FedEx、DHL、UPS、EI、DSV 分别设置 0%–100%。
  FedEx 抽中一票时检查查询主页和详情页；所有承运商统一检查 PDF 有效性、
  运单号和送达状态，不再检查签名。结果写入 `pod_audit.xlsx`。
- Excel 合并与核对：检验表和 Droplist 可同时处理，也可任选一侧单独合并；
  对应输出 `合并检验表.xlsx` 或 `合并Droplist.xlsx`。
  已选一侧会生成对应文件，界面未选侧保持空白。两侧都有数据时按日期与
  光联/MPO 归总类别比较数量。检验表明细仍保留澳车、港车、814S 等原类型，
  `类型箱数` Sheet 另行汇总每天各原类型的箱数。检验表与 Droplist 还会按
  Shipment 聚合多行数量，识别数据缺失、运单错误和数量不对；点击异常汇总行
  可查看 Shipment 和原因，完整明细写入 `Shipment异常` Sheet。
- 设置分四个标签页：连接与路径（FedEx API、EI 账号、默认路径、实际浏览器）、映射
  （文件名映射）、货代抵达状态（可为 DHL、EI、DSV 添加额外状态，仅与当前状态完整
  匹配）、POD 抽查比例（五个承运商各自填写 0–100 的整数）。
- 官网语言：DHL（hk-en）、UPS（loc=en_US）由 URL 决定；DSV、EI 没有语言参数，
  程序把浏览器 Accept-Language 与 navigator.language 锁成 en-US，页面若仍为中文
  再兜底点击站点自带的 English 选项，保证状态文案与英文选择器一致。
- FedEx 网页 POD：批量任务先用 API 查状态，送达票进入「FedEx POD 任务中心」。
  自动/手动开关切换界面，默认自动；自动可选连续或分段，默认分段。
  手动模式由用户操作 TRACK 和详情，主页、详情各点一次“保存”；两页完成后
  自动复制下一票，不跳转或提交网页。失败后“恢复”从有效 PDF 的下一阶段继续。
  自动下载遇到任何失败会暂停当前票，恢复可重试，也可切换手动继续。
- 自动与手动模式都可导入单列运单 Excel；有无表头均可。刷新只保留本次查询及
  本次导入的运单记录，不删除已有 PDF。自动分段下载最多处理 100 票，超过 50 票按
  25 票分段；每票间隔 15 秒，段间休息 5 分钟。连续模式处理当前队列的全部待办票。
- UPS POD 打印前会清除 Cookie、复制提示、聊天和助手浮层。
- 设置中可指定 POD 整理目录；跟踪页“一键整理 POD”只把结果中已下载的
  POD PDF 直接移到该目录并更新 Excel 路径，目录、非 PDF、不存在路径和同名文件
  会被安全忽略，不会移动、删除或重命名来源文件夹。
- 映射设置提供包含/完全/正则匹配方式、真实文件名预览和推荐规则补充；
  使用说明见 `docs/FILENAME_MAPPING_GUIDE.md`。
- 更新：启动后静默检查新版本；左下角“应用信息”可查看版本、更新日志或手动检查。
- 跟踪页的“结果操作”集中放置结果文件、POD 抽查、整理和 FedEx 任务中心入口；
  右侧固定栏在窄窗口自动折叠；“运行日志”在表格下方独立显示，不会让工具栏覆盖表格。

界面中的 POD 绿色圆点、查询结果、清洗文件、POD 抽查和两份合并 Excel
均可直接点击打开。

跟踪与 Excel 合并使用独立后台任务，可以同时运行；两页各自保存输出路径，
切换页面或完成另一项任务不会清除已经生成的文件按钮。

文件名映射由界面写入 `data/filename_mappings.json`。每条规则保存文件名关键字、
检验表原类型和用于核对的归总类别；归总类别只允许光联或 MPO。FedEx API
Secret 和 EI 密码使用当前 Windows 用户的 DPAPI 加密后写入设置文件。

## FedEx 逻辑（2026-10-27 修订）
- 先 trackingnumbers 正常查主单（非 MPS）——无子单运单以官网状态为准
- associatedshipments 返回 2–39 件时，所有可见关联单全部送达才算送达
- 返回达到 40 件时，40 件全部送达则暂定送达，并写入人工复核备注
- API 只负责快速查询状态，不再请求官方 POD 文档接口
- 只有送达后才进入 FedEx POD 任务中心；任务数据库保存到本次输出根目录
- 手动模式中由用户提交查询、打开详情并点击“保存”，程序单次识别后保存：
  `运单号.pdf` 为查询主页，`运单号+.pdf` 为详情页
- 两页完成后自动复制下一票；用户仍需点击 TRACK，程序不自动提交
- 自动模式使用真实 Microsoft Edge 和官网运单页面；失败票进入暂停状态并保留有效 PDF 阶段
- 网页 PDF 打印前自动关闭 Cookie 和聊天浮层
- 界面中的同一个绿色 POD 圆点会依次打开这两份文件

## FedEx POD 任务中心操作

1. 在自动/手动开关选择处理方式；自动模式还可选连续或分段。
2. 两种模式均可导入仅有 A 列运单的 Excel；A1 可为“运单号”表头，也可直接是第一票。
3. 点击“开始”。手动模式打开受控浏览器并复制当前运单；用户点击 TRACK 和详情，
   分别点“保存”。第二页保存成功后自动复制下一票，网页仍由用户操作。
4. 点击“暂停”会等当前运单完成再暂停；“恢复”优先重试失败运单，并从有效主页
   PDF 后的阶段继续。自动下载遇到网络/网页错误也会自动暂停。
5. 点击“刷新”只保留本次主查询和本次导入运单；旧队列记录移除，已下载 PDF 保留。
6. 分段最多 100 票；50 票以内一段，超过 50 票按 `25 + 25 + ...`，票间 15 秒，
   段间 5 分钟。置顶开关默认关闭。

## Droplist 识别
- 日期优先从文件名读取，没有日期时逐级读取祖先文件夹，并统一输出 `2026/9/10`
- 路径明确含 MPO 或光联时归入对应类别；无法确认时进入未识别清单，不再默认归光联
- 明细 Sheet 按归一化表头识别常见订单、Shipment 与数量字段，支持不同表头名称和行号
- 点击“Droplist 自检”可查看未识别表头的文件与具体 Sheet
- 首个汇总页、`Address`、默认 `Sheet1` 和空表不计入合并数量
- A-D 全空，或宽表的 I-K 全空时，视为有效数据结束
- 检验表以 N 列 `Shipment` 的最后一个有效值为截止，只复制带 Shipment 的业务行
- 合并 Droplist 时一次建立当天光联/MPO 完整运单索引；检验表只抽取少量有效运单匹配。明确命中的总类型优先于文件名和结构提示；同时命中两类时人工确认
- 细分业务优先使用映射中的详细名称，未配置时保留去日期与总类型前缀后的文件名，不必为每个新名称增加规则
- 工作表结构和文件名用于运单未命中时辅助识别，分类依据写入明细的映射备注
- 核对汇总按日期比较光联/MPO 数量，并按 Shipment 进一步核对缺失、运单和数量；异常行可点击查看详情
- 未识别文件不占核对汇总行、不计入正常数量；处理后弹窗可复制文件名或打开所在文件夹

## 2026-10-09 缺陷修复

- EI 当前状态优先读取与 Status 标签配对的页面字段，路线和历史事件不会混入当前状态；Delivered 与 Completed 均可识别为送达。
- FedEx 半自动会在 about:blank、新标签、跳转、旧标签关闭或上下文失效后重新发现有效的 FedEx Tracking 页面，并拒绝非 FedEx 域名或 FedEx 非查询页。
- 官网页面仍由用户操作并直接打印为 PDF；没有使用 API 数据拼装页面，也没有改用官方 POD 下载。

## 1.5 映射规则

- 匹配前自动忽略文件名开头日期、空格、大小写和 `-`、`_`、`—` 等分隔符。
- 检验表详细类型可以留空；归总类别必须填写光联或 MPO。
- 例如 `9.22MPO国外FEDEX自提—空运出货资料` 可由 `MPO国外FEDEX自提`
  规则归为 `FedEx自提 / MPO`。

## 1.1 浏览器与更新

- DHL、UPS、EI、DSV 使用电脑已安装的 Microsoft Edge 或 Google Chrome，
  不再依赖 Playwright 下载的模拟 Chromium 浏览器。
- DSV 详情页依次尝试实际结果链接、文字元素和结果卡片位置点击。
- DHL 的 Delivered 只允许来自当前状态区域，历史事件全文不再确认送达。
- 设置页可直接验证 FedEx API；OAuth token 按 API 凭据隔离。
- 更新文件下载后必须通过 SHA-256 校验，程序退出后再安全替换 EXE。

## 1.2 POD 抽查

- 设置中的五个比例互相独立，0% 表示不抽查，100% 表示全部抽查。
- 抽查表字段为运单号、承运商、POD 类型、抽查比例、查询状态、POD 文件、
  PDF 有效、运单号匹配、PDF 提取状态、送达状态匹配、结果和说明。

## 合并异常处理

- 检验表原始列宽不一致时，按最大列数保留所有源列，再追加类型、日期等映射字段。
- 缺失文件不会被虚构；异常文件页会列出缺失的日期/类别和无法匹配的文件。
- 以 2026-09-21 附件复核：9.19 光联加入 Expeditors 映射后两侧均为 1,917；
  9.18 MPO 缺检验表源文件，9.17 MPO 差 98，9.19 MPO 差 355，仍需核源。
